你在 ChatGPT 里敲下一句话，它开始一个字一个字地往外蹦。三秒后，你得到一段通顺、得体、有信息的回答。

这背后没有一份"请假邮件生成规则库"，只有一台从"猜下一个词"里长出来的统计机器。为了真正看懂它，这篇按照《从零构建大模型》的路线，把一条 GPT-2 级别的小模型（约 1.24 亿参数）从零搭起来，再顺着**数据工程 → 预训练 → 后训练 → 在线推理**四道工序，把每一步的底层机制讲透。

## 一、神经网络基础：模型到底在算什么

### 1.1 最小单元：线性层与激活函数

神经网络能处理语言，起点是两个最小零件：**线性层 + 激活函数**。

线性层做的事是 y = Wx + b。输入一个 768 维向量，乘一个 768×768 的权重矩阵，加一个偏置，输出另一个 768 维向量。它本质上是"搬运/检测"：按固定规则把输入特征变换一遍。但它有一个致命局限——**线性变换是全体统一行动的**：同一个矩阵作用在向量的每个元素上，无法针对某个元素单独做决定。

激活函数（LLM 里常用 GELU）做的事是"判断/筛选"：**看输入的值决定怎么处理**——正的放行、负的压制，而且是逐元素的。

### 1.2 为什么必须非线性

把两层线性叠起来：W₂(W₁x + b₁) + b₂ = (W₂W₁)x + (W₂b₁ + b₂)，还是线性。**叠多少层都只是一条直线。** 只有引入激活函数，网络才真正"拐弯"。

这意味着：

- **线性 = 全体统一行动**；
- **激活 = 逐个做决定**；
- **复杂逻辑 = 层层决定组合出来的**（无数个"如果 A 且 B，则 C"式的筛选叠在一起）。

这也是为什么激活函数不能省、也不能用纯线性近似——没有非线性，再深的网络也只是更大的尺子。

### 1.3 学习：损失函数 + 梯度下降

模型怎么"学"？三步：

1. **前向**：输入数据，得到预测；
2. **算损失**：用一个损失函数衡量"猜错多少"。分类和语言模型都用交叉熵——预测给正确答案的概率越高，损失越小；
3. **反向更新**：梯度下降算出每个参数应该往哪个方向调多少，让下次猜对的概率高一点点。

所谓"参数"，就是所有可训练的权重矩阵和偏置。1.24 亿参数、几万亿次"猜 → 错 → 调"，就是预训练的全部内容。

## 二、数据工程：把人类文本变成数字

神经网络只认识数字。把人类文本变成数字，是数据工程的第一件事，也是整条流水线里**最不可逆的决策**。

### 2.1 Tokenizer：不可逆的翻译官

Tokenizer 把文本切成一个个 token，每个 token 分配一个 id。GPT-2 用 BPE（字节对编码）：从字符/字节开始，反复统计并合并最高频的相邻对，直到词表达到目标大小（50257 个 token）。常见词占一个 token，生僻词被拆成子词。

这个翻译官有两个隐藏代价：

- **语言效率差异**：同一个意思，中文在英文 tokenizer 下可能被拆成 3–6 个 token，而英文约 1 个。序列更长 → 注意力按平方增长 → 更慢更贵。Qwen/DeepSeek 训练 tokenizer 时拉高中文数据配比，把中文字压到约 1 个 token；
- **不可逆**：一旦选定 tokenizer，所有训练数据都用它编码，embedding 空间的语义坐标已经定型。换 tokenizer = 全部数据重新编码 + 旧权重作废。这是比架构、学习率都更根本的决策。

### 2.2 Embedding 与位置编码

**Embedding（词嵌入）**：一个查表操作，把 token id 映射成向量（768 维）。这张表 [50257, 768] 是可训练的——训练后，语义相近的词在向量空间里距离更近（"猫"和"狗"比"猫"和"宪法"近）。

**位置编码**：Transformer 本身没有顺序概念，必须显式告诉它每个 token 在第几位。GPT-2 用可学习的绝对位置嵌入 [1024, 768]；现代模型多用 RoPE（旋转位置编码）这类固定函数，用相对位置信息替代绝对位置。

### 2.3 语料准备与数据规模

预训练语料要清洗：从 HTML 提取正文、去重、过滤低质文本，通常要扔掉 50%–80% 的原始数据。真实大模型的预训练语料以万亿 token 计；书里用一本小说就能把 124M 的小模型训起来——规模是工程问题，不是原理问题。

微调语料则完全不同：分类微调要标注好的 (文本, 标签)，指令微调要 (指令, 回答) 对。**质量远重要于数量**——几百条干净标注往往胜过几万条噪声数据。

### 2.4 三种任务，三种数据形态

| 阶段 | 数据形态 | loss 计算位置 |
|---|---|---|
| 预训练 | 纯文本（整本书/语料切块） | 所有 token 位置 |
| 分类微调 | (文本, 标签) | 每个样本最后一个 token |
| 指令微调 | (指令, 回答) 对 | 只算回答部分 |

这里提前预告一个贯穿全文的关键概念——**两类 mask 别混淆**：

- **因果注意力 mask**：模型结构层的，限制 token 只能看左边，永远生效；
- **损失 mask**：训练数据层的，决定哪些位置参与 loss（指令部分、padding 部分设 -100 忽略）。

## 三、模型架构：Transformer 解码器

### 3.1 自注意力：让 token 互相"看"

注意力是 Transformer 的核心。每个 token 都会生成三个向量：**Q（查询）、K（键）、V（值）**。然后：

1. 用当前 token 的 Q 和序列里所有 token 的 K 做点积，得到"相似度"；
2. 除以 √d_k 缩放（防止点积过大把 softmax 推到饱和区）；
3. softmax 变成权重；
4. 用权重对 V 加权求和，得到这个位置的输出。

可以类比查字典：Q 是你要查的问题，K 是词条索引，V 是词条内容。注意力让**任意两个 token 一步直接交互**——这正是它比 RNN 强的地方：RNN 要沿着序列一步步传递信息，长距离依赖会衰减；注意力一步直达，而且所有位置可以并行计算（本质是矩阵乘法）。

### 3.2 因果掩码与多头注意力

语言模型的任务是"根据上文预测下文"，所以注意力必须**只看过去**：把未来位置的相似度设为 -∞，softmax 后权重变成 0——这就是因果掩码，也叫自回归掩码。

**多头注意力**：不是算一个注意力，而是把 768 维拆成 12 个头（每头 64 维）并行算，再拼接起来过输出投影。不同头可以关注不同的模式：语法角色、指代关系、局部短语、全局语义……各司其职。

### 3.3 TransformerBlock：四件套

每个 Transformer 块是四件套的循环：

```text
x → norm1 → 多头注意力 → 残差相加 → norm2 → 前馈网络 → 残差相加 → 输出
```

两个细节值得注意：

- **Pre-Norm（先归一化再计算）**：现代 LLM 把 LayerNorm 放在子层之前，残差路径上的信号几乎原样传递，深层网络更好训练——这也是"为什么模型里到处是归一化"的答案；
- **残差连接**（x + F(x)）：让梯度有一条直通到底的高速公路，是深层网络能训起来的物理基础。

### 3.4 LayerNorm 与 FFN 的细节

**LayerNorm** 对每个 token 的向量做标准化：减去均值、除以标准差，再乘可学习参数 γ、加 β。公式：

```text
x̂ = (x − μ) / √(σ² + ε)
y = γ · x̂ + β
```

它和 BatchNorm 的关键区别：**只依赖当前 token 自己的向量**，不依赖 batch 里的其他样本，所以训练和推理行为一致、能处理变长序列。作用是稳定激活尺度、让梯度不爆炸不消失——把"脚下的地面抹平"，每一步踩得实。

**FFN（前馈网络）**：768 → 3072 → 768，中间放大 4 倍，激活用 GELU。两个线性层之间必须有激活，否则两层可合并成一层（见 1.2）。4 倍是经验选择：表达能力与计算成本的折中。

### 3.5 参数量：124M 花在哪了

| 组件 | 参数量 |
|---|---|
| Token 嵌入 50257×768 | ≈ 38.6M |
| 位置嵌入 1024×768 | ≈ 0.8M |
| 12 个 Transformer 块（每块注意力 4×768² + FFN 2×768×3072 + 两个 LayerNorm） | ≈ 85M |
| 输出头 768×50257（与 token 嵌入共享权重） | ≈ 38.6M（共享后不计） |
| **合计（共享后）** | **≈ 124M** |

两个要点：**大头在 FFN 和嵌入/输出层**；GPT-2 的输出头和 token 嵌入共享同一份权重（weight tying），这既是省参数，也是一种正则。

## 四、预训练：所有能力从"猜下一个词"涌现

### 4.1 任务定义

预训练只做一件事：**给定上文，猜下一个词。**

取一段文本，遮住下一个词，让模型预测；猜错了，调整参数；换一段文本，重复几万亿次。模型从来没有被教过语法、逻辑、事实——它只是让"在上文 X 下，下文 Y"的预测概率越来越高，把语言的统计规律内化进参数。"法国首都是"后面大概率是"巴黎"，不是因为有人标注过，而是因为这句话在语料里出现了成千上万次。

### 4.2 训练循环

```python
for batch in train_loader:
    # batch: (8, 1024) 的 token id，8 条样本、每条 1024 个位置
    logits = model(batch)                    # 前向 → (8, 1024, 50257)
    loss = cross_entropy(
        logits.flatten(0, 1),                # (8×1024, 50257)
        targets.flatten()                    # 每个位置的"真实下一个词"
    )
    loss.backward()                          # 反向：算出每个参数的调整方向
    optimizer.step()                         # 更新所有参数
```

三个细节：

- **目标错位构造**：第 t 个位置的 target 是第 t+1 个 token，所以模型在每个位置都在预测"下一个词"；
- **所有位置都参与 loss**：预训练处处都在学"语言规律"，这正是它和微调的本质区别；
- **因果掩码保证不偷看**：预测位置 t 时，注意力只能看到 t 及其左侧。

### 4.3 评估：loss、困惑度与准确率

预训练期间的评估非常简单：**看 loss**。配套指标是困惑度（perplexity = exp(loss)）。loss 持续下降说明在学；不降说明训练出了问题（数据、学习率、梯度）。

还有一个容易误解的指标：**准确率**——模型预测的 top-1 词是否等于真实下一个词。书里 124M 模型训完准确率约 46%。听着很低？词表有 50257 个 token，纯随机猜中的概率只有约 0.002%——46% 已经说明模型深刻理解了语言。准确率在预训练里只是参考，loss 才是主指标，因为**目标只有一个**。

### 4.4 训练稳定性：三根支柱

- **Warmup（学习率预热）**：训练初期 embedding 梯度极端稀疏（每步只激活词表中极少 token），优化器需要先积累梯度统计，否则头几万步盲走；
- **梯度裁剪**：异常 token 组合会产生单步超大梯度，一次更新毁掉前面几亿步的积累，必须限制更新上限；
- **Weight Decay**：对 2D 权重矩阵施加衰减防过拟合；对 1D 参数（LayerNorm 的 γ/β）不施加，因为它们的优化方向不是"趋向于零"。

### 4.5 产物：只会续写的 Base Model

预训练产出的是 Base Model：它能续写"床前明月 → 光，疑是地上霜"，但不会聊天。你问它"法国的首都是什么"，它可能把你的问题原样续写一遍——因为预训练语料里，对话格式极少出现，而论坛引用格式才是常态。

预训练只教会了语言，没教会对话。所以有了后训练。

## 五、后训练：1% 的成本改变 100% 的体验

预训练花掉约 95% 的算力，后训练只花 1–2%，但**你日常感受到的体验差异，大部分是后训练决定的**。后训练分三步。

### 5.1 分类微调：教它做判断题

给模型换一个分类头（768 → 2），然后选择性解冻：

```python
model.out_head = nn.Linear(768, num_classes)   # 换头
for param in model.parameters():
    param.requires_grad = False                # 先全部冻结
for param in model.trf_blocks[-1].parameters():
    param.requires_grad = True                 # 解冻最后一个 Transformer 块
for param in model.final_norm.parameters():
    param.requires_grad = True                 # 解冻最后的 LayerNorm
```

几个要点：

- **参数量策略**：124M 模型只训练约 5.7% 参数。微调数据量小（几千条），全量训练几乎必然过拟合；底层学的是通用特征，越靠近输出越任务相关，所以只动最后一层；
- **损失计算**：每个样本取最后一个真实 token 的隐藏状态 → 分类头 → 2 个 logits → 交叉熵。一个样本只贡献一个误差；
- **两个局限**：信息瓶颈（整个文本的判断压在一个 token 上）+ 换头即锁死（模型永远只会做这一件事）。

### 5.2 指令微调：教它做问答题

数据是 (指令, 输入, 回答) 三元组，先格式化成一段文本：

```text
Below is an instruction that describes a task. Write a response that appropriately completes the request.

### Instruction:
把下面这句话翻译成英文

### Input:
今天天气很好

### Response:
The weather is nice today.
```

训练目标和预训练完全一样——**还是猜下一个词**。唯一的区别在 loss：

```text
targets: [-100, -100, ..., -100, "The", "weather", ..., EOS, -100, -100]
          ↑ 指令/输入部分忽略        ↑ 回答部分有效   ↑EOS保留  ↑padding忽略
```

关键细节：

- **mask 是损失过滤器，不是输入删除键**：指令部分照常参与前向和注意力计算，只是不贡献 loss；
- **EOS 结束符保留为有效 target**：让模型学会"回答完就停止"，推理时遇到 EOS 才停；
- **padding 也设 -100**：补出来的 token 没有语义，不参与 loss。

参数策略上，先演示全量微调，再用 **LoRA**：冻结原始权重 W，在旁边注入两个低秩矩阵 A、B，只训练它们：

```text
W_eff = W + (α/r)·A·B
W: 768×768（冻结）   A: 768×r   B: r×768   r 取 4–16
```

为什么低秩够用？研究发现微调时权重的真实变化 ΔW 往往集中在**低维子空间**——有效改动方向不多，低秩分解刚好抓住主要部分。初始化时 A 随机、B 全零，所以训练起点 ΔW=0，模型行为和基座完全一致。可训练参数从 124M 降到约 0.1%（约 15 万），效果接近全量微调。

一个核心洞察：**SFT 不注入新知识**。预训练读过的 token 比几十万条对话多几个数量级，SFT 教不会新知识——它只是把已有能力"引导"到对话行为上。所以指令微调的天花板 = 基座模型的能力上限。

### 5.3 对齐：从"能说"到"会说好"

SFT 之后模型会聊天，但不保证说好话。对齐技术经历了三次简化：

- **RLHF**：训练一个奖励模型打分，再用强化学习（PPO）优化策略，四个网络协同；
- **DPO**：发现可以用偏好对（好回答 vs 差回答）直接优化，砍掉独立的奖励模型；
- **GRPO**：进一步用组内归一化替代价值网络，只剩一个网络。

对齐始终伴随 **Alignment Tax**：模型越"听话"（客气、安全、有帮助），在 MMLU 这类知识测试上的分数可能越低——对话数据中的礼貌模式会压缩预训练建立的更全面的知识分布。越听话，可能越笨，这是真实的取舍。

### 5.4 后训练的评估：和预训练完全不同

预训练看 loss 就行，因为目标单一；后训练目标复合，必须分层评估：

| 层面 | 指标 | 回答的问题 |
|---|---|---|
| 任务指标 | F1、格式合规率 | 任务做好了吗？ |
| 能力回归 | MMLU 子集保留率 | 通用能力退化了吗（灾难性遗忘）？ |
| 偏好 / 指令质量 | AlpacaEval、MT-Bench、LLM 裁判 | 回答更受欢迎吗？ |
| 人工抽验 | 专家评审 | 理由可信吗？幻觉多吗？ |

工程口诀：**任务指标定生死、能力基准防退化、裁判模型做对标、人工抽验兜底**。注意 LLM 裁判有三个已知偏差：位置偏差（随机交换顺序平均两次）、长度偏差（偏爱长回答，用长度控制）、自偏好（别用被测模型的同族当裁判）。

## 六、在线推理：一个字一个字地"说"

训练结束，模型上线。推理和训练用同一个模型，但运行方式完全不同：**推理没有标准答案，模型要自己生成。**

### 6.1 自回归生成

生成过程：输入 prompt → 模型预测第一个 token → 把 token 追加到输入 → 预测第二个……直到生成 EOS 停止。**一次只能蹦一个词**，这是推理延迟的根本来源。

### 6.2 解码策略：为什么不能总选概率最高的

模型在每个位置输出词表上的概率分布，怎么从中选词？

- **greedy**：每次选概率最高。稳定、可复现，但容易陷入重复和无聊的文本；
- **temperature**：把分布压平（T 大）或拉尖（T 小），控制随机性：p_i ∝ exp(z_i / T)；
- **top-k / top-p**：只在概率最高的前 k 个（或累计概率达到 p 的最小子集）里采样，防止从超长尾里选出乱码。

这就是同一句话问两次、回答可能不同的原因——推理带随机性（除非 temperature=0）。

### 6.3 KV Cache：显存换速度

每生成一个新 token，注意力都要和之前所有 token 交互。不缓存的话，每次都要把前面全部 K/V 重算一遍——计算量随生成长度平方增长。**KV Cache 把中间结果存下来**，用显存换速度：只算新 token 的 Q，与缓存的 K/V 做注意力。

代价是显存：缓存大小 ≈ 层数 × 头数 × 头维度 × 序列长度 × 精度。上下文越长、并发越高，缓存越大。3B 模型开满长上下文时，KV Cache 可能比权重本身还大。GQA（多头共享 KV，缓存直接砍 75%）、KV 量化，都是在为这条物理约束做优化。

### 6.4 部署：量化与显存

以 3B 模型为例，权重在不同精度下的显存占用：

| 精度 | 权重占用 | 说明 |
|---|---|---|
| FP16/BF16 | ≈ 6.5 GB | 原样精度 |
| INT8 | ≈ 3.5 GB | 有少量精度损失 |
| INT4（AWQ/GPTQ/GGUF Q4） | ≈ 2 GB | 部署主流，通常损失 1–3 个百分点 |

4GB 显存的卡（甚至纯 CPU + 8GB 内存）就能跑 INT4 的 3B 模型。推理是永续成本——训练是一次性投入，推理是每天在烧钱，所以量化、批处理、吞吐优化（vLLM 这类框架）是常态。

## 七、全景总结：一条流水线，两种"学习"

把四道工序串起来：

- **数据工程**决定模型"吃"什么——文本变成数字，不可逆；
- **预训练**让模型学会语言——交叉熵 + 梯度下降，几万亿次"猜下一个词"，评估只看 loss；
- **后训练**让模型学会行为——分类微调学判断、指令微调学对话、对齐学说好话，评估分层；
- **在线推理**把所学变成逐 token 的输出——自回归 + 解码策略 + KV Cache + 量化。

一句话版本：**数据工程喂教材，预训练学语言，后训练学行为，推理时一个字一个字地"想"出来。**

还有一个贯穿始终的观察：预训练和后训练用的是**同一台机器**——交叉熵 + 梯度下降。变的从来不是"怎么训练"，而是四件事：**教什么（数据）、让哪些参数学（冻结/LoRA）、学多快（学习率/轮数）、怎么算成绩（评估）**。

## 核心结论

1. 神经网络 = 线性（搬运）+ 激活（判断）层层组合；没有非线性，再深的网络也只是更大的尺子。
2. Tokenizer 是不可逆的翻译官：选错等于数据管线和旧权重全部作废。
3. 注意力让任意两个 token 一步交互，因果掩码保证只看过去，多头让不同头关注不同模式——这是 Transformer 取代 RNN 的物理原因。
4. 预训练只做"猜下一个词"，但语言、知识、推理全部从这里涌现；评估只看 loss，因为目标单一。
5. 预训练和后训练是同一台机器，差别只在"教什么、让哪些参数学、学多快、怎么算成绩"。
6. 后训练 1% 的成本改变 100% 的体验；SFT 改行为不改知识，天花板是基座能力；对齐有 Alignment Tax。
7. 推理是逐 token 的自回归，KV Cache 和量化是在"显存换速度"这条物理约束下的工程博弈。
8. 评估必须分层：任务指标定生死、能力基准防退化、裁判模型做对标、人工抽验兜底。
