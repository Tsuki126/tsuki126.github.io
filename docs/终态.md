# 博客终态

本文档是本博客的目标状态约定。所有改样式、改结构、改写作流程的动作都以这里为准；与本文冲突的临时方案一律以本文为准。

## 一、定位

一个安全工程师的公开输出系统，三个用途按重要性排序：

1. **给面试官/同行看**：作品与判断力的证据，简历上直接放链接。
2. **给自己的知识沉淀**：可检索、可复用，学习 → 思考 → 实践形成闭环。
3. **长期写作习惯的载体**：每天有记录，每周有产出。

## 一之二、个人操作系统（定位升级）

### 首页文案（已定稿）

> **探索未知，思考本质，实践真知**
> 安全工程师，记录企业安全体系的建设与思考
> 最近在关注：AI 与智能体安全、云原生攻防，以及如何把经验写成系统。
> 动作行：从这里开始 ↓ · 索引 → · 关于我 → · RSS ↗

首页区块顺序（只此一种）：**h1 = Tsuki126** → 座右铭 → 身份行 → 动作行 → 从这里开始 → 最近更新。

导航品牌（已定稿）：**缺口环图标**（一个未闭合的圆环，1.6px 圆头描边，22×22）。

- 图标不写字：导航只留标志，名字交给首页 h1（Tsuki126），两者不再复述同一个名字。

约定：

- 首页只放"信条 + 身份记录"两行，**不再加设计的定位语**（反复验证过：任何改写的文案都不如原句）。
- 首页不列举经历、不做自我评价（"都做过"这类表述不放首页）。
- 身份与关键词的承载位置：`hugo.toml` 的 `description`（搜索与分享卡片）放置"安全工程师 · 企业安全体系 · AI 安全 · 云原生 · 数据安全"；关于页开头放经历证据（云、数据、主机、网络、应用）；栏目结构（索引/博客/随笔）表达内容范围。

站点不只是"对外的博客"，而是**个人操作系统**：把工作、专业能力、安全技术以及生活输入，持续记录成可检索、可复用的资产。

### 三个记录轴

| 轴 | 记录什么 | 载体 | 公开性 |
| :--- | :--- | :--- | :--- |
| **安全技术** | 八个方向的学习、实践与判断（智能安全、应用安全、网络安全、主机安全、容器安全、云安全、数据安全、安全攻防） | 博客长文 + 索引页 | 公开 |

| **工作实践** | 项目复盘、案例、决策与结果（**脱敏后**） | 复盘文章 | 公开为主，敏感内容私有 |

### 私有层约定

个人操作系统必须区分公开与私有：

- **公开层**：`content/` 下正式内容，随站点发布。
- **私有层**：本地 `notes-private/`（或 `content/**/draft=true`）保存不适合公开的工作细节，只留在本地，不进 Git 或只进私有仓库。
- 判断标准：涉及公司项目细节、客户信息、未公开漏洞、同事评价的内容一律不进公开层。

### 未来的数据层（批 4）

把"记录"变成"可度量"：写作频率与连续周数、课题闭环数量、各方向内容分布、阅读与学习投入。先定义数据来源与更新方式，再动手。

## 二、信息架构

| 页面 | 路径 | 职责 | 视角 |
| :--- | :--- | :--- | :--- |
| 首页 | `/` | 门面与分流：品牌 → 座右铭 → 身份 → 动作行 → 「从这里开始」精选 → 「最近更新」双栏 | 编辑 |
| 索引 | `/index/` | 导航大脑：说明 → 检索 → 分区网格（专业 8 / 人生 6）→ 按时间浏览 → 全部标签 | 地图 |
| 文章 | `/blog/` | 专业内容的**时间流**：定位句 + 两行筛选（方向 / 类型）+ 按年分组 | 读者 |
| 随笔 | `/notes/` | 日常记录的**时间档案**：定位句 + 主题筛选 + 年 → 月归档 | 读者 |
| 关于 | `/about/` | 简历落地：定位 + 经历 + 精选 + 联系方式 | 招聘方 |

导航顺序：**首页 · 索引 · 文章 · 随笔 · 关于**；左上角为缺口环图标（仅图标，带 `aria-label`）。

URL 约定：`/blog/<slug>/`、`/notes/<slug>/`、`/directions/<slug>/`、`/tracks/<slug>/`、`/stages/<slug>/`。

### 四页分工原则

- **索引按"结构"找，文章与随笔按"时间"找**——两者互补，不重复。
- 每页顶部都有一句定位，读者永远知道这页是什么。
- 首页只放精选与最新，不放统计；数据与导航集中在索引页。
- 详情页（文章/随笔）才有面包屑、上一篇/下一篇与标签。

## 三、分类体系

三个正交维度，全部以 Hugo taxonomy 实现；**front matter 键用复数**（Hugo 约定）：

| 维度 | front matter | 取值 | 作用 |
| :--- | :--- | :--- | :--- |
| 方向 | `directions` | `ai-security` / `application-security` / `network-security` / `host-security` / `container-security` / `cloud-security` / `data-security` / `security-offense-defense` | 专业区分组（8 个） |
| 主题 | `tracks` | `reading` / `investing` / `health` / `language` / `exploring` / `life` | 人生区分组（6 个） |
| 类型 | `stages` | `learning` / `thinking` / `practice` / `output` | 内容形态（学习/思考/实践/输出） |

- 显示名与定位说明集中在 `data/partitions.yaml`，投稿只写英文 slug。
- `tags` 负责细粒度检索；`series` 负责连载聚合。
- 索引页的**实线格 = 已有内容，虚线格 = 已规划**；分区名与说明永远显示，避免"空目录"。

## 三之二、内容形态：学习 / 思考 / 实践 / 输出

站点的主表述是"安全技术的学习、思考、实践与输出"，落地为第二个维度 `stage`：

| 形态 | 含义 | 典型内容 |
| :--- | :--- | :--- |
| 学习 | 输入与消化 | 读书笔记、课程笔记、论文/文章笔记、概念梳理 |
| 思考 | 形成判断 | 体系化长文、观点、方法论、复盘 |
| 实践 | 动手验证 | 实验、复现、工具、项目、踩坑记录 |
| 输出 | 对外交付 | 成文发布、分享/讲课、开源、被复用的结论 |

约定：

- 每篇博客打一个 `stage`（必要时可多个），作为**轻量标注与筛选**，不做成空矩阵分区（避免"待补充"式的刻意感）。
- 列表与索引页在标题后显示形态小标签（如"思考"），读者可据此判断内容类型。
- 首页副标题直接表达这条闭环：**记录安全技术的学习、思考、实践与输出**。

## 四、内容规范

- **每日随笔**（`/notes/` 或 `/notes/<日期>/`）：见闻 / 思考 / 待验证 三段，10 分钟能写完。front matter：`date`、`tags`、`source`。
- **每周课题**（`/blog/`）：每周 1-2 个，必须走完"学习 → 实践 → 思考"闭环才发布。front matter：`direction`、`tags`、`series`、`description`。
- **每篇必须包含**：能提出的问题、动手验证的过程、可复用的结论。
- **学习源**：FEEI.CN（吴飞飞的公开知识库）为主，主机/容器/云方向补 CIS Benchmark、云厂商白皮书、Kubernetes 官方文档。

## 五、视觉规范

- **基调（已定稿）**：采用方案 A——**中性灰阶配色 + 宋体正文**（照搬 FEEI.CN 的真实参数），底色 `#fafafa`、表面 `#fff`、正文 `#262626`、次级 `#666`、弱化 `#999`、边框 `#e5e5e5`、链接下划线 `#bdbdbd`；正文 1.05rem 宋体（Songti SC），引用用楷体；暗色映射见 `docs/设计规范.md`。
- **首页 h1**：`Tsuki126`，字号 2.0rem。
- **首页行序**：品牌（Tsuki126）→ 座右铭 → 身份行 → 动作行 → 从这里开始 → 最近更新。
- **首页**：保留封面图作为视觉锚点；不加动效、渐变、光斑、架构图装饰。
- **列宽**：正文 720px（当前 880-960px 偏宽，中文一行 45+ 字）。
- **排版**：正文 16px / 行高 1.8；文章标题与列表标题统一规格。
- **标题编号**：文章正文的 h2/h3 用「1. / 1.1.」编号（文档感，便于引用）。

### 从 FEEI.CN 借鉴的部分（只借系统，不借皮）

**借鉴**：每个大板块有入口页；文章页左侧同方向文章树 + 右侧目录；随笔按年→月归档；文章显示"最后更新"与"复制原文"；面包屑与目录高亮；把写作规范文档化（即本文）。

**不借鉴**：灰阶无彩色配色、全站衬线正文、文档站的整体气质、个人生活数据（健康/财务）。

## 六、交互清单

**做**：宽屏侧栏目录 + 中等屏可折叠目录；灯箱支持 Esc 与焦点管理；代码块语法配色与复制按钮；图片懒加载；外链新标签 + `rel`；RSS 入口；深色模式跟随系统。

**不做**：站内搜索（内容量不足时先不加）；评论系统；阅读进度条；访问统计；首页动效。

## 七、技术规范

- 样式集中在 `static/css/main.css`（含设计令牌），不再往 `custom_head.html` 里堆内联 CSS。
- 作用域用显式 class（如 `.post-page`），不用 `main:has(h1)` 这类脆弱选择器。
- 不为了适配深色偏好而用 `!important` 硬覆盖亮色。
- 代码高亮统一为 class 模式（`noClasses = false`）+ `static/css/chroma.css`。
- front matter 约定固定：`direction`、`tags`、`series`、`description`、`showToc`。
